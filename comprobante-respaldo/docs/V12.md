# Probar V12 con dos iPhone y un Android

Trabaja en Safari normal en los iPhone y en Chrome normal en Android. Usa el mismo navegador, dirección y puerto durante toda la prueba. Cada teléfono tendrá su propio sello y su propia copia del historial.

## Abrir la rama experimental sin publicar

Una copia de esta rama se puede servir como archivos estáticos. La página de GitHub Pages corresponde a la versión publicada. El enlace de un archivo en github.com muestra el código fuente.

**En cada teléfono, sin PC ni Codespaces.** Puedes usar una terminal local con Python 3 (por ejemplo, iSH en iOS o Termux en Android). Si ya tienes una copia descomprimida del repositorio, ejecuta el último comando desde su raíz. Para descargar la rama, usa una carpeta nueva en la terminal:

```sh
# iSH: instala Python si hace falta
apk add python3 ca-certificates
# En Termux el comando equivalente es: pkg install python
```

```sh
mkdir -p ~/phersaa-prueba
cd ~/phersaa-prueba
python3 -c "import urllib.request; urllib.request.urlretrieve('https://github.com/PherSAA/split-run/archive/refs/heads/feature/phersaa-v12-comprobantes.zip', 'v12.zip')"
python3 -m zipfile -e v12.zip .
cd split-run-feature-phersaa-v12-comprobantes
python3 -m http.server 8000 --bind 127.0.0.1
```

Abre **http://127.0.0.1:8000/comprobante-respaldo/presupuestos/** en ese teléfono. Mantén disponible la terminal durante la primera carga. Espera **Disponible sin internet en este navegador** antes de desconectarte. El servidor de archivos solo escucha en ese dispositivo. La aplicación guarda los presupuestos en el navegador y los intercambia mediante archivos. La preparación de iSH y Termux y el cambio entre apps requieren comprobación en hardware real.

También sirve una copia de la rama en un origen HTTPS privado al que ya tengan acceso los teléfonos. Cada uno debe completar la primera carga. Un servidor HTTP en una IP de la red local no ofrece el contexto seguro que requieren el sello y el service worker.

## Recorrido de aceptación

| Paso | Dispositivo y acción | Qué comprobar |
| --- | --- | --- |
| 1 | iPhone A: abre **Ejemplo de drywall · $650** y pulsa **Firmar y guardar**. Exporta el JSON y envíalo al iPhone B. | V1 contiene $200 de paneles, $50 de tornillos y compuesto, y $400 de instalación. |
| 2 | iPhone B: guarda el JSON en Archivos, toca **Importar archivo** y pulsa **Aceptar versión**. Exporta y devuelve el archivo a A. | A importa la respuesta y ve **Aceptado** en V1. En el detalle aparecen la huella completa de V1 y el sello del revisor. |
| 3 | A y B: antes de intercambiar nada más, pulsen **Proponer cambios**. A cambia el precio unitario de instalación a $450. B lo cambia a $430. Ambos firman. | A obtiene $700 y B $680. Ambos son V2 con huellas distintas. Cada uno muestra **Sin revisiones para esta versión**. B puede probar **Rechazar versión** en su V2. |
| 4 | Android: recibe ambos JSON y carga los dos con **Importar archivo**. | **Propuestas en conflicto** muestra $700 y $680 con sus partidas. También debe funcionar importándolos en el orden inverso. |
| 5 | Android: en la propuesta de $680 toca **Resolver con esta propuesta**. Cambia la instalación a $440 y firma. Exporta y envía a A y B. | Los tres obtienen V3 de $690 tras importar. En **Ver huella y sello** hay dos versiones anteriores. El historial conserva V1 y ambas V2 con sus revisiones. |
| 6 | A: abre **Historial de versiones**, busca V1 y pulsa **Recuperar como nueva versión**. Firma. | V4 vuelve a $650. La aceptación continúa asociada a V1. V4 queda sin revisar. |
| 7 | Activa modo avión tras preparar la caché. Cierra la pestaña y abre de nuevo la misma dirección. Crea o edita otra partida, firma, exporta a Archivos/Descargas y recarga. | El historial, el sello y las nuevas cantidades persisten. Se puede importar un JSON guardado en el dispositivo. |
| 8 | Importa una copia de un JSON cuyo precio hayas cambiado en un editor de texto. Repite con texto que no sea JSON. | Aparece **Archivo rechazado** y se conserva el presupuesto previo. |

En iOS, localiza el JSON exportado en las descargas de Safari y compártelo desde Archivos. En Android, usa Descargas o el selector de archivos. Si el sistema renombra los JSON repetidos, conserva nombres distintos como `A-700.json` y `B-680.json`. Usa la huella del contenido para distinguir las propuestas. Para documentar la prueba anota modelo, sistema, navegador, total y primeros 12 caracteres de la huella de cada versión; usa solamente datos de ejemplo.

## Pruebas reproducibles

Desde la raíz del repositorio, con Node 22+, Python 3 y navegadores de Playwright:

```sh
node --test tests/v12/protocolo.mjs
python -m pip install playwright==1.55.0
python -m playwright install --with-deps webkit chromium
python tests/v12/telefonos.py
```

El flujo **PHERSAA V12 · Intercambio móvil** ejecuta estos comandos. WebKit y Chromium en Linux usan tamaños de pantalla, toque y perfiles móviles emulados. La prueba trabaja con tres contextos de navegador independientes, archivos descargados desde la interfaz, dos pestañas que editan una base común y un servidor local que se apaga durante la recuperación sin internet. El uso de Safari, Archivos, Chrome y Descargas en teléfonos físicos se debe registrar por separado.

## Alcance y límites

- USD, cantidades con dos decimales, precio en centavos y redondeo de cada subtotal al centavo. Máximo 32 partidas por versión, 240 registros por historial y 8 MiB por archivo. Al alcanzar el límite se conserva lo guardado.
- Una revisión es un registro firmado sobre un hash SHA-256, incluso cuando dos propuestas tienen el mismo número de versión. Se muestran todos los votos recibidos. La aplicación no atribuye cargos, autoridad comercial ni identidad legal.
- Cada archivo incluye el historial conocido por quien lo exporta y un índice firmado. La aplicación verifica firmas, estructura y referencias antes de guardar. Al importar combina la información con la copia local. El equipo solo conoce las propuestas que recibe.
- El archivo contiene partidas e importes legibles. Quien lo reciba puede revisarlo, crear propuestas con otro sello y devolverlas. No hay cuentas, lista de participantes ni autorización de firmantes. Usa información de prueba.
- La primera apertura requiere acceso a los archivos de la aplicación. La cámara, AirDrop y servicios de mensajería no son necesarios para verificar. La disponibilidad de esos canales depende del dispositivo.
- Borrar los datos del navegador, cambiar de origen o usar una sesión privada puede hacer inaccesibles los registros y el sello local. Un JSON exportado recupera el historial, pero no la clave privada. Exporta después de firmar cambios importantes.
